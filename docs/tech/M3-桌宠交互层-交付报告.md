## 三、关键设计落地说明

### 3.1 窗口角色机制（pet / panel / setup 三窗共享 preload）

为避免维护三份 preload 脚本，主进程在创建 BrowserWindow 时通过 `webPreferences.additionalArguments` 注入 `--petibi-role=<role>`：

```ts
new BrowserWindow({
  webPreferences: {
    preload: join(__dirname, '../preload/preload.js'),
    additionalArguments: ['--petibi-role=panel'],
  },
})
```

preload 脚本读取 `process.argv` 识别角色，同一份 contextBridge 按角色决定 `openPanel/hidePet` 等方法是否实际转发（其他角色下调静默 noop），保证渲染进程只看到自己需要的 API，避免误调。

### 3.2 单击 vs 拖拽判定（≤5px 阈值）

```ts
// 距离平方严格大于 25（=5²）即视为拖拽
const totalDx = e.screenX - press.startX
const totalDy = e.screenY - press.startY
if (!press.moved && totalDx * totalDx + totalDy * totalDy > CLICK_VS_DRAG_THRESHOLD_SQ) {
  press.moved = true
}
```

- **mouseup 时 `!press.moved`** → 单击 → `petApi.openPanel()`
- **mouseup 时 `press.moved`** → 拖拽过阈值 → 视为拖拽，不发面板
- 边界值用例在 `decide-click-drag.test.ts` 覆盖：(5,0) 单击 / (4,4) 拖拽 / (-5,0) 单击等 10 个回归

### 3.3 桌宠思考动画 ≤0.3s 切换（PRD §3.4 硬性指标）

ChatTab 发送瞬间立即调用 `window.petState('thinking')`：

```ts
setThinking(true)                       // ≤0.3s 内
thinkingSinceRef.current = Date.now()
...
for await (const evt of streamChat(token, text)) {
  setMessages((prev) => applyChatEvent(prev, evt, id))
  if (isTerminalEvent(evt)) finishThinking()  // meta/done/error 切回 idle
}
```

`finishThinking()` 用 `THINKING_MIN_MS = 250ms` 兜底：若 mock 模式秒回，桌宠思考动画至少显示 250ms，保留"拟人互动"的体感；连发时不会覆盖在途的 thinking 状态。

### 3.4 关闭按钮只 hide、托盘驻留

- 桌宠窗 `close` 事件：`e.preventDefault()` + `petWin.hide()`，进程不退出
- 面板窗 `close` 事件：同上
- `window-all-closed` 改为：仅 `isShuttingDown` 时才 `app.quit()`
- 托盘启动即创建（setup 阶段也已驻留），菜单 `显示桌宠 / 隐藏桌宠 / 退出` 三项

### 3.5 SSE 流式对话（mock + 真接口双路）

`src/api/client.ts` 暴露统一 `streamChat(token, question, options)` 异步生成器：

```ts
export async function* streamChat(token, question, options) {
  if (USE_MOCK) {
    yield* mockStreamChat(token, question, options.onQuotaConsumed)
    return
  }
  yield* realStreamChat(token, question, options.signal)
}
```

事件序列与 server 契约 §4 完全对齐：`{type:'meta'} → {type:'delta', text}* → {type:'done', total_chars}` / `{type:'error', message}`。mock 模式按字切片（每 3 字一块）模拟流式体感，便于 dev 体验。

reducer 抽取到 `src/panel/chat-reducer.ts` 独立纯函数，便于 12 个 vitest 用例覆盖；ChatTab.tsx 仅做事件循环与 React 状态联动。

### 3.6 4 Tab + 占位策略

`App.tsx` 用 `activeTab` state 切换 4 个 Tab；其中"对话"完整实现，"百科 / 社区 / 我的" 三个 Tab 走 `<PlaceholderTab title=... description=... />` 统一组件，统一显示：

```
[模块名]
[一句话功能描述]
[即将上线]
```

后续工单实现各模块时直接替换 PlaceholderTab 即可，不影响 App.tsx 路由。

### 3.7 DB 选型与不动 server

本工单严格不动 `server/`：chat/quota 接口完全沿用 M3 对话链路工单已落地的实现。`scripts/verify_panel.py` 在 `PETIBI_DB_PATH=data/verify_panel.db` 临时数据库下独立跑 server（不污染默认 `server/data/chat.db`），跑完即删除。

## 六、已知偏差与遗留

| 项 | 说明 | 影响 |
|---|---|---|
| `npm run build` 中的 `electron-builder` 步骤 | 需联网下 electron 二进制，本机 Win 镜像已配 `electron_mirror` 但仍可能慢；本次用 `npm run build:app` 覆盖 | 干净机器/Mac 上跑 `npm run build` 即可出安装包；M1 阶段已产出可分发的 NSIS 包（82MB） |
| 拖拽 vs 单击阈值的几何含义 | 实现用 `dx²+dy² > 25`（严格大于），故对角 4+4 距离≈5.66px 是拖拽，水平 5px 距离是单击 | 与 PRD "位移 <5px 视为单击" 一致；用户抖动 ≤5px 不误触面板 |
| 托盘图标复用 sprite | 复用 `resources/sprites/intj/idle_0.png` 作为托盘图标（32×32 系统托盘自动缩放） | 视觉上桌宠与托盘图标风格统一；如需通用化图标后续单独设计 |
| 面板 token 来自本地 `userData/profile.json` | panel 启动期通过 IPC `panel:get-init` 读本地档案，不读 server | 加速首屏；如本地档案缺失则提示「请先完成初始化」 |
| mock LLM 拒绝模板 | `REFUSE_KEYWORDS` 与 server `data/intent-filter.json` 关键词不完全对齐（mock 自带） | dev 体验足够覆盖 5 类越界；生产接真 LLM 后意图过滤走 server，无此偏差 |
| thinking 帧 | `App.tsx` 的 `FRAMES.thinking` 暂复用 idle 帧 | 状态切换逻辑完整，仅 sprite 待美术工单（M4） |
| 跨平台路径 | `db.ts` 用 `fileURLToPath` 解析项目根（已有，M3 工单实现） | Win/macOS/Linux 一致 |
