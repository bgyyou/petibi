## 2. 问题定性

重复分三种，成因不同：

1. **trait 尾巴拼接（重灾区，占 58 / 91）**：早期生成时给每个人格准备了一个
   "人格万能句池"（如 ENFJ 的『被人需要时会更有动力』『不擅长拒绝，需要刻意练习』），
   4 条 trait 各自从池子里抽 2–4 句拼在正文后面凑字数，导致同一句在 2–3 条 trait 里重复，
   且与条目自己的 title 完全不相干（『责任感强』里讲『对情绪氛围极敏感』）。
   ISTJ / ISFJ / ESTJ / ESTP / ESFP / ISFP 的 4 条 trait 几乎是同一段话的排列组合。
2. **FAQ 开头固定式（33 条里的大多数）**：`作为 XXXX，通常会…` / `作为 XXXX，会把…`
   这类开场白被 2–8 条 FAQ 共用，INTJ 一家就有 8 条 FAQ 以 `作为 INTJ，通常` 开头。
   （上一轮清的是 FAQ **结尾**的万能句，开头没动。）
3. **认知功能收尾句复用**：`是 Ni 的模型建构本能`（INTJ×2）、`是 Te 的效率本能，但`（ENTJ×2）、
   `是 Si 的稳态偏好，`（ISTJ×2）、`是 Se + Fi 的`（ESFP×3）等。

## 3. 工具

| 文件 | 作用 |
|---|---|
| `scripts/scan_entry_overlap.py`（新增） | 全类目扫描：同人格内任意两条目的**极大公共子串** ≥N 字（默认 10）全部列出，含条目 id / category / title；`--cross` 附带跨人格抽查；`--json` 落盘；退出码 0 = 干净，可作 CI 卡口 |
| `scripts/apply_entry_dedup_patches.py`（新增） | 按 id 覆写 content 的补丁应用器。只改 content，不动 id/category/title/tags/scenario；保持 2 空格缩进 + 中文不转义 + CRLF，diff 只落在被改的行；未知 id 直接报错退出 |
| `scripts/patches/M4-dedup/*.json` | 本轮 10 个补丁文件（改写内容留痕，可复查/回滚） |

同人格扫描用 DP 求极大公共子串；跨人格扫描用 10-gram 索引（O(总字数)），
因为任何 ≥10 字的共享片段必然共享至少一个 10-gram，索引不漏报。

## 4. 改写原则

1. **一句话只留在语义最贴的那条目里**，其余条目改写为围绕自己 title 展开的新内容。
   例：ENFJ 的『对情绪氛围极敏感』保留在 trait-02「高度社交敏感」，
   trait-01/03/04 各自改写为『照顾者』『责任感』『自我牺牲』的具体画面。
2. **不串场**：改写后的句子必须能被 title 直接管住，不再往正文后面拼人格通用句。
3. **字数守规范**：trait 80–150、faq 120–200（`check_encyclopedia.py` 硬卡）。
   本轮有 3 轮补丁是专门把改写后掉到 80 字以下的 trait 补回合规区间（batch2b / batch3b / batch4b）。
4. **FAQ 只动冲突的那一小段**，正文里的具体建议原样保留，避免把上一轮清干净的尾巴弄回去。
5. 保留原有文风：『』引号、Fe/Ni/Te 认知功能术语、口语化的具体建议。
