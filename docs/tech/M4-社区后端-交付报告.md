# M4 社区后端 + 内容审核管道 交付报告

## 任务概述

工单要求（PRD §3.7 + 红线 R7/R8）：

1. **社区后端**：5 张表（posters / comments / likes / share_counts / moderation_logs）+ 6 个接口（POST/GET 海报、点赞、留言、分享计数）；
2. **审核管道（红线 R7 核心）**：所有 UGC 必经内容审核，`status != approved` 的内容**任何列表接口都不可见**；
3. **合规页面（红线 R8）**：隐私政策 + 用户协议静态页可访问。

## 实现摘要

### 1. 数据库 schema 迁移（`server/src/db.ts`）

在 `ensureSchema()` 末尾追加 5 张表 + 5 个索引：

| 表 | 关键字段 | 说明 |
|---|---|---|
| `posters` | id / user_id / image_path / persona_type / question_excerpt / answer_excerpt / status / likes / created_at | 海报主表；status='pending'\|'approved'\|'rejected' |
| `comments` | id / poster_id / user_id / content / status / created_at | 留言主表；同样三段式 status |
| `likes` | user_id / poster_id / created_at（UNIQUE(user_id, poster_id)） | 幂等点赞；UNIQUE 约束防止重复计数 |
| `share_counts` | user_id / count（PK= user_id） | 累计分享数；V2 装扮解锁依赖 |
| `moderation_logs` | content_type / content_id / user_id / provider / decision / reason | **R7 审计证据**：每次审核动作（含 pass）必落日志 |

**关键索引**：`posters(status, created_at DESC)` 让广场列表只走 approved 时间倒序；`comments(poster_id, status, created_at)` 让留言列表走同一过滤；`moderation_logs(content_type, content_id)` 让 R7 抽查可按内容回溯。

### 2. 错误码 + 类型（`server/src/errors.ts`）

新增 4 个错误码：

- `InvalidPoster`（400）— 海报参数非法（缺字段、超长、base64 格式错）；
- `ContentRejected`（语义保留）— 实际响应里返回 `{ status: 'rejected', reason: '...' }` 给前端做用户反馈；
- `ContentPending` — 语义保留；
- `CommentTooLong`（400）— 留言超 200 字；携带 `extra: { maxLen, actualLen }`。

`AppError` 类已支持 `extra` 字段透传，统一错误处理中间件在 `app.ts` 已正确展开。

### 3. 内容审核管道（`server/src/moderation.ts`）

**抽象接口**：

```ts
export interface ModerationProvider {
  readonly name: string
  moderateText(text: string): Promise<ModerationResult>
  moderateImage(imageBase64: string): Promise<ModerationResult>
}

export interface ModerationResult {
  decision: "pass" | "reject"
  category?: string
  matchedKeyword?: string
  reason: string
  provider: string
}
```

**默认实现 `LocalModeration`**：

- 基于 `data/sensitive-words.json` 的**子串匹配 + 大小写不敏感 + 去标点空白**；
- 词库按 `categories: [{ name, keywords[] }]` 组织，**支持热加载**：新增类目/词条不需要改代码；
- `moderateImage` MVP 期一律 pass（base64 合法性校验在路由层做），**云厂商接口位已留好**（PETIBI_MODERATION_PROVIDER 切换 + env 读密钥）。

**`createModerationProvider()` 工厂**：

- 读 `PETIBI_MODERATION_PROVIDER` env，未知值/未配置 → 降级回 `local`，避免误配导致 500；
- **密钥永远不进仓库**：env 缺失时降级而非报错；后续接 AliyunGreen / TencentIMS 时在该函数加 case 即可。

### 4. 路由（`server/src/routes/posters.ts`）

| 端点 | 鉴权 | 说明 |
|---|---|---|
| `POST /api/posters` | 必 | 上传海报（base64 图片存 `server/data/posters/<uid>/<ts>.<ext>`，≤2MB；先入 pending → 审核 → approved 才响应） |
| `GET /api/posters` | **公开** | 广场列表，只返 `status='approved'`，按 `created_at DESC, id DESC`，分页 limit/offset |
| `POST /api/posters/:id/like` | 必 | 幂等点赞/取消；UNIQUE(user_id, poster_id) + 事务保证 likes 表不重复计数 |
| `POST /api/posters/:id/comments` | 必 | 留言 ≤200 字；先入 pending → 审核 → approved；海报不存在或未 approved 返回 404 |
| `GET /api/posters/:id/comments` | **公开** | 留言列表，只返 `status='approved'` |
| `POST /api/me/share-count` | 必 | UPSERT 累加；返回累计 count（V2 装扮解锁） |

**关键不变量（红线 R7 强制点）**：

- 路由 SQL 全部硬编码 `WHERE status = 'approved'`，**不依赖业务代码"记得过滤"**——即使将来写错代码，未审核内容也不会泄露；
- pending / rejected 内容**对作者本人也不可见**（广场/留言列表都不返回）；
- 每次审核动作（含 pass）必写一条 `moderation_logs`，供 R7 审计与未来训练数据回放；
- 海报上传路径：`/api/posters` 入口鉴权 → 参数校验 → 图片存盘 → INSERT pending → 调审核管道 → 写日志 → UPDATE status；任一环节失败抛 AppError 由统一中间件处理。

### 5. App 装配 + 静态页面（`server/src/app.ts` + `server/public/*.html`）

- `/privacy` 与 `/terms` 直接 `app.get(...)` + `res.sendFile(...)` 返回 `server/public/{privacy,terms}.html`；
- `/data/posters/*` 通过 `express.static` 托管上传图片，避免前端拿 path 后 404；
- `/api/posters` mount 不挂全局 auth，把 `auth` 中间件注入路由，**GET 类按需不加 auth**（公开），POST 类按路由粒度挂 auth；
- 路由工厂 `createPostersRouter({ db, config, moderation, auth })` 接收依赖，单测可直接 supertest(createApp())。

### 6. 词库（`data/sensitive-words.json`）

**MVP 占位词库**，仅覆盖常见广告引流/刷单/轻度辱骂：

- 22 条 ad（兼职/加微信/刷单/代购/包邮/拼多多/互关等）；
- 10 条 abuse（笨蛋/废物/滚/去死/弱智等）；
- 0 条 spam（连续同一字 ≥8 次，规则在 LocalModeration 留位但本期不实现）。

**总计 32 条**，JSON 顶部带 owner_note 说明：

> 正式敏感词库（涉政/涉黄/涉暴/涉恐）由 owner 从合规渠道导入后追加；LocalModeration 支持热加载追加词表，无需改代码。

### 7. 合规页面（`server/public/privacy.html` / `terms.html`）

**隐私政策**（R8 必含要素）：

- 数据收集清单表（邮箱/昵称/MBTI/宠物昵称/聊天记录/海报/留言/分享计数）；
- 存储位置（SQLite 本地 + posters 图片本地）；
- 用户权利（查看/修改/注销/删除）；
- 第三方共享（LLM 服务商 + 内容安全 API）；
- 未成年人保护（14 岁提示）；
- 政策变更 + 联系方式。

**用户协议**：

- 产品说明 + AI 内容免责声明（明确非专业意见）；
- UGC 规则（禁政治/色情/暴恐/辱骂/广告引流等）+ 审核机制 + 违规处理；
- 年龄提示（14 周岁以上）；
- 知识产权 + 协议变更 + 法律适用 + 联系方式。

## 附录：终审复跑发现的回归（已修复）

### 现象

终审在另一时段复跑 `npx vitest run`（根目录全量），发现 `server/tests/auth.test.ts` 的两个用例失败：

```
FAIL  配额 HTTP /api/quota > 直接读写库模拟已用 2 次后，remaining = 1
  expected +0 to be 2
FAIL  配额 HTTP /api/quota > 已用满 → remaining = 0，used = limit
  expected +0 to be 3
```

### 根因（不是我引入的回归）

`git diff HEAD -- server/src/routes/quota.ts server/src/quota.ts server/src/utils/date.ts server/tests/auth.test.ts` 输出为空——M4 工单没碰这四个文件；diff 仅在 `server/src/db.ts` 新增 5 张表（posters / comments / likes / share_counts / moderation_logs），与 `chat_usage` 表无关。

真正的根因是测试里的**潜伏时区 bug**：

| 调用方 | 日期生成方式 | 时区 |
|---|---|---|
| `GET /api/quota` 路由（`server/src/routes/quota.ts`） | `todayDateString(now)` 来自 `utils/date.ts`：`now.getFullYear()` + `getMonth()` + `getDate()` | **本地** |
| `server/src/quota.ts` 里的 `getTodayUsage` | `todayKey()` 同款本地逻辑 | **本地** |
| `server/tests/auth.test.ts` 失败用例 | `new Date().toISOString().slice(0, 10)` | **UTC** |

`toISOString()` 强制输出 UTC `YYYY-MM-DD`，而应用层用本地日期。两者在 UTC+8 机器上的**冲突窗口**：

- 本地 00:00–08:00 ↔ UTC 前一天 16:00–24:00 → **日期相差 1 天**，测试写 `2026-08-13`，查询走 `2026-08-14`，`getTodayUsage` 查不到记录返回 0；
- 本地 08:00–24:00 ↔ UTC 同一天 00:00–16:00 → 日期一致，测试通过。

我交付时跑测试的时间是 **21:46 本地**（落在"安全窗口"），所以 `250/250 通过`；终审在 **00:07 本地**（落在"窗口外"），两个用例就 fail。

`/api/chat` 的 `consumeOrThrowQuota` 也用 `todayKey()` 写本地日期，所以**生产路径不受影响**——只影响直接写库模拟"已用 N 次"的少数测试用例。

### 修复

把两个失败用例的日期生成从 `toISOString().slice(0, 10)` 改为应用同款 `todayKey()`（从 `../src/quota.js` 导入），并加注释解释为什么不能用 UTC：

```ts
import { todayKey } from "../src/quota.js"

// 用应用同款的 todayKey()（本地时区 YYYY-MM-DD）写库，否则跨时区时 UTC 切片
// (toISOString) 与本地日期相差一天，会导致 GET /api/quota 读到错日期返回 0。
const date = todayKey()
env.db
  .prepare("INSERT INTO chat_usage (user_id, date, count) VALUES (?, ?, ?)")
  .run(userId, date, 2)
```

没改应用代码、没改断言、没改 db schema；**只让测试和应用走同一时区**。
