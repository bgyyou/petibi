# M3 对话链路接口契约（派单前必读）

> 用途：人格资产生产（速查卡/拒绝模板/意图词库）与 RAG 对话链路开发并行时的接口约定。
> 对应：docs/tech/M3-AI对话模块设计.md、PRD §3.4、红线 R3/R4。

---

## 1. 人格速查卡 `data/personas/<type小写>.json`

```json
{
  "type": "ENTP",
  "pet_name": "狐狸",
  "animal": "狐狸",
  "family": "analyst",
  "system_prompt": "【身份】…【风格】…【认知】…【边界】…【禁止】…",
  "cognitive": ["Ne", "Ti"],
  "style_keywords": ["幽默", "爱挑战", "比喻"]
}
```

- `system_prompt` 五段式（身份/风格/认知/边界/禁止），**≤200 字**，模板见 M3 设计文档 §3.2
- `pet_name`：16 只各起一个 2 字中文名（顺口、有人格味）

## 2. 拒绝模板 `data/refusals.json`

```json
{
  "categories": ["code", "homework", "generate", "web", "roleplay"],
  "templates": {
    "ENTP": { "code": ["……", "……"], "homework": ["……"], "generate": ["……"], "web": ["……"], "roleplay": ["……"] }
  }
}
```

- 16 人格 × 5 类越界 × 每类 2 条变体 = 160 条
- 每条 ≤80 字，人格化口吻（参考 M3 设计文档 §5.4 示例），必须含"引导回聊天"的收尾；禁止"对不起/我无法"开头

## 3. 意图过滤器词库 `data/intent-filter.json`

```json
{
  "rules": [
    { "category": "code", "keywords": ["写代码", "python", "bug", "编程", "代码"], "action": "refuse" },
    { "category": "web", "keywords": ["天气", "股价", "新闻", "热搜"], "action": "refuse" }
  ],
  "rag_skip_patterns": ["你好", "早上好", "晚安", "谢谢", "哈哈"]
}
```

- `action: refuse` → 命中直接走拒绝模板，不调 LLM；`rag_skip_patterns` → 闲聊不触发 RAG
- 5 类越界 = code / homework / generate / web / roleplay

## 4. 后端 API 契约（server/）

技术栈（已定 P2-003）：**Node.js + Express + better-sqlite3**，无状态 API。

| 接口 | 说明 |
|---|---|
| `POST /api/auth/email/code` | 发邮箱验证码（body: {email}；dev 模式验证码直接返回在响应里并打日志，生产接邮件服务） |
| `POST /api/auth/email/verify` | 校验并登录（body: {email, code} → {token, user}；新用户自动注册） |
| `GET /api/me` | 当前用户信息（含 mbti/subtype/nickname） |
| `POST /api/me/profile` | 初始化写档（nickname + mbti + subtype） |
| `POST /api/chat` | 对话（SSE 流式）。流程：意图过滤 →（命中则流式返回拒绝模板，不计 LLM 调用但计次）→ 配额检查（每日 10 次，R4）→ RAG 检索 Top1 → 拼 prompt → DeepSeek 流式 |
| `GET /api/quota` | 今日剩余次数 |

DB 表：`users(id, email UNIQUE, nickname, mbti, subtype, created_at)` / `email_codes(email, code, expires_at)` / `chat_usage(user_id, date, count, UNIQUE(user_id,date))` / `chat_logs(id, user_id, question, answer, rag_entry_id, created_at)`（rag_entry_id 供 R3 溯源抽查）

RAG 检索：MVP 用关键词/tag 匹配（question 与 entries 的 tags/scenario/title 做简单打分取 Top1），不引向量化依赖；检索结果写入 chat_logs。

## 5. LLM 接入

- DeepSeek 兼容 OpenAI 接口（`https://api.deepseek.com`，model 如 `deepseek-chat`，base_url/key 走环境变量 `DEEPSEEK_API_KEY`，**key 不进仓库**，`.env.example` 占位）
- 未配置 key 时：返回 mock 流式响应（便于前端开发），日志标注 [mock]
- 输出限制 ≤150 字（prompt 约束 + max_tokens 兜底）
