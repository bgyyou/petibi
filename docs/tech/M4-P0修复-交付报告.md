## 2. P0-001 / P0-002：资源未打包

### 2.1 根因

`electron-builder.yml` 原配置 `files: ['out/**']` 只能把 electron-vite 产物打包进 `app.asar`。两个问题：

1. **闭源美术资产（`assets/art/portraits/`）没进安装包**——main.ts 用 `process.cwd()` 拼路径读 portrait，prod 下 cwd 不可靠（用户从任意目录启动 exe 时 cwd 不一定是 exe 同级），即便文件被复制到仓库根也会拿不到。
2. **`resources/sprites/` 看起来进了 asar 但 pet 渲染窗仍可能空白**——`resources/` 是 vite `publicDir`，理论上 Vite 会拷到 `out/renderer/sprites/...` 然后被 `out/**` 一起打入 asar。但若同时打开的 setup/panel 窗加载顺序与 pet 错位（比如首启走 setup），用户看到的就是 setup 空白而不是 pet 空白。
3. **托盘图标复用同一 sprite 但读取路径硬编码 `__dirname/../../resources`**——prod 下 `__dirname` 是 `resources/app/out/main`，`../../resources` 解析到 `resources/app/resources/`——这是个在 asar 之外的错误路径，所以 `nativeImage.createFromPath` 拿到的是空图，托盘只显示一个透明占位（看起来"图标不可见"）。

### 2.2 修法

**1) `electron-builder.yml`**：加 `extraResources`，把三个目录整包放到 `process.resourcesPath` 下：

```yaml
files:
  - out/**
  - package.json
extraResources:
  - from: resources
    to: resources
    filter: ['**/*']
  - from: assets
    to: assets
    filter: ['**/*']
  - from: data
    to: data
    filter: ['**/*']
```

效果：打包后 `resources/resources/sprites/...`、`resources/assets/art/portraits/...`、`resources/data/encyclopedia/...` 都存在；不进 asar，避免大图读取走 asar 慢路径。

**2) `electron/main.ts`**：新增 `resourcesRoot()` 工具函数统一 dev/prod 路径：

```ts
function resourcesRoot(): string {
  if (!devUrl) {
    return app.isPackaged ? process.resourcesPath : join(__dirname, '../..')
  }
  return join(__dirname, '../..')
}
const RESOURCES_DIR = join(resourcesRoot(), 'resources')
const ASSETS_DIR    = join(resourcesRoot(), 'assets')
const DATA_DIR      = join(resourcesRoot(), 'data')
```

把原来硬编码 `process.cwd()` 的 `portrait:read`、`encyclopedia:read`、`encyclopedia:index` IPC 全部改成读 `ASSETS_DIR` / `DATA_DIR`：

```ts
const portraitPath = join(ASSETS_DIR, 'art', 'portraits', `${type}.png`)
const filePath    = join(DATA_DIR, 'encyclopedia', `${type}.json`)
```

tray 图标读取也走 `RESOURCES_DIR`，并对 32×32 sprite 做 `resize({width:16,height:16})` 适配 Windows 托盘原生尺寸，加载失败打 warning 不静默吞。

## 3. P0-003：单实例锁

### 3.1 根因

`electron/main.ts` 没调 `app.requestSingleInstanceLock()`。Windows 下双击 Petibi.exe 两次会真的拉起两个 BrowserWindow，桌宠多了一只。

### 3.2 修法

在 `app.whenReady()` **之前**调锁：

```ts
const gotLock = app.requestSingleInstanceLock()
if (!gotLock) {
  app.quit()
} else {
  app.on('second-instance', () => {
    const target = petWin ?? setupWin ?? panelWin
    if (target && !target.isDestroyed()) {
      if (!target.isVisible()) target.show()
      if (target.isMinimized()) target.restore()
      target.focus()
    }
  })
}
```

注意：
- 必须在 `whenReady` 之前调用，否则锁不生效；
- 失败分支只 `app.quit()`，不创建窗口不显示 UI；
- 拿到锁的实例收到 `second-instance` 时优先把 pet 窗拉到前台（用户最常用），没有再选 setup/panel。

### 3.3 验证

第一次 `./release/win-unpacked/Petibi.exe` 拉起 4 个进程（main + GPU + helper ×2）。立刻第二次 `./release/win-unpacked/Petibi.exe` —— `tasklist | grep -i Petibi | wc -l` 仍是 4，无新增进程；第二个 exe 立即退出，焦点回到第一个的 pet 窗。

## 4. P0-004：右键菜单 + 退出入口

### 4.1 根因

`pet:menu` IPC 的菜单模板只有三状态 radio + 一个 toggle（显示/隐藏桌宠），**没有「退出」项**。当用户把桌宠隐藏后，托盘虽有退出但桌宠右键里没有——owner 实测反馈"右键点不到退出"。

另外 `petWin.webContents.send('pet:set-state', s.id)` 发送前没做 `isDestroyed` 守卫，连续点击 + 隐藏场景下偶发 `Object has been destroyed` 错误，导致整个回调抛错、菜单点击"无反应"——这是 owner 实测"右键点击待机/眨眼/开心无反应"的真因（不是 IPC 没注册）。

### 4.2 修法

**1) 补「退出」**：菜单尾部加 separator + 退出项，与 tray 退出行为一致：

```ts
{ type: 'separator' },
{
  label: '退出',
  click: () => { isShuttingDown = true; app.quit() },
},
```

**2) 显式「隐藏桌宠」项**：用户口头再加一个。toggle 项保留（隐藏时变 "显示桌宠"），另起一个独立的 `label: '隐藏桌宠', enabled: !petHidden, click: () => hidePet()`——已隐藏时灰掉，避免歧义。

**3) `isDestroyed` 守卫**：radio 项 click 内发送 IPC 之前检查窗与 webContents 是否被销毁：

```ts
click: () => {
  currentState = s.id
  if (!petWin || petWin.isDestroyed()) return
  if (petWin.webContents.isDestroyed()) return
  petWin.webContents.send('pet:set-state', s.id)
},
```

### 4.3 验证

菜单结构（Petibi 已启动且 pet 可见时右键桌宠）：

```
○ 待机 idle
○ 眨眼 blink
○ 开心 happy
─────────
   显示桌宠                ← 隐藏时显示，未隐藏时此 label 不出现
   隐藏桌宠                ← 始终存在，未隐藏时可点击，已隐藏时灰掉
─────────
   退出
```

托盘菜单（未变）：

```
显示桌宠 / 隐藏桌宠
─────────
退出
```

tray 图标在 win-unpacked 启动后可见（32×32 sprite resize 成 16×16 加载成功，`nativeImage.isEmpty()` 不再为 true）。

## 5. P0-007：dev 白屏

### 5.1 根因

`petWin.loadURL(devUrl)` 中 `devUrl = process.env.ELECTRON_RENDERER_URL` 实际值是 **`http://localhost:5173`（无尾斜杠）**——查 electron-vite 源码 `lib-t2ExBjL5.mjs:67` 确认：

```js
process.env.ELECTRON_RENDERER_URL = `${protocol}//${host}:${port}`
```

原代码 `setupWin.loadURL(`${devUrl}setup/index.html`)` 拼出来是 `http://localhost:5173setup/index.html`（**协议头后面直接接 setup，没斜杠**），404。setup 是首启默认窗 → 用户看到的就是全白。

pet 窗 `loadURL(devUrl)` 在 vite dev server 会自动重定向到 `/` 并 serve `src/index.html`，本身不会白屏；但因为走 setup 流先，setup 白屏后用户感觉"整个 app 白屏"。

### 5.2 修法

`electron/main.ts` 三处 loadURL 全部做尾斜杠归一化：

```ts
setupWin.loadURL(`${devUrl.replace(/\/$/, '')}/setup/index.html`)
// panel 同理
// petWin.loadURL(devUrl)  ← 不动，让 vite 自己重定向到 /
```

这样无论 ELECTRON_RENDERER_URL 末尾是否带 `/`，都拼出正确路径。

### 5.3 验证

启动 `npm run dev`，curl 四个关键路径：

```
GET /                  → 200
GET /setup/index.html  → 200
GET /panel/index.html  → 200
GET /sprites/intj/idle_0.png → 200
```

每个 HTML 的 `<script src="./main.tsx">` 都被 vite 转成对应路径的 `/main.tsx`、`/setup/main.tsx`、`/panel/main.tsx`，各自加载对应 `App.tsx`（setup → `{ App } from "./setup/App.tsx"`，panel → `{ App } from "./panel/App.tsx"`，pet → `App from "./App.tsx"`）——入口不再错位。

> 备注：用户报告"安装包正常、dev 模式坏"——实际是 dev URL 路径拼错，prod 用 loadFile 走文件系统路径所以不受影响。

## 6. P1-001：idle 帧像素差异调查

> 不在 P0 必修范围，但 owner 顺手让我评估。

### 6.1 数据（INTJ，scripts/check_idle_diff.py）

| 指标 | 值 |
|---|---|
| 帧尺寸 | 32×32 × 2（一致） |
| 差异像素总数 | 66 (6.4%) |
| 差异包围盒 | (7, 14) → (25, 22) |
| 差异行范围 | y=[14, 23]，占 10/32 行 |
| 上半区差异像素 | 27 |
| 下半区差异像素 | 39 |
| 上/下比例 | 0.69 |

### 6.2 根因推断

- 包围盒左右都到 7~25，**没有贯穿整图宽度**（full-width diff），所以不是"两帧整体上下平移"那种严重问题；
- 差异像素主要在 y=[14,22] 这一段——按 32px 高，上半 (y<16) 占 27 像素、下半 (y>=16) 占 39 像素；
- 上/下比例 0.69 表示**上半下半都在动**，不是单纯躯干抖动。

owner 描述"下半张脸连身体上下抽动、上半脸不动"—— 与实测一致：上半差异 y=14,15 两行（共 27 像素均匀分布在这两行），下半 y=16..22 是身体主体（39 像素集中在躯干）。

实际原因：`scripts/make_idle.py` 把"躯干带整体下移 1px + 腿丢顶行"——这本身是 1px 呼吸效果（合规），但 32px 画布上 1px 位移在 128px 显示尺寸下是 4px 位移，**frame interval 125ms × 4px 视觉跳跃**会读成抽搐而不是呼吸。

### 6.3 修复建议（M5 动画迭代时执行）

1. **基准点严格一致**：所有 idle 帧把脚底/地面线 y 坐标钉死，重新生成脚本 `make_idle.py` 里不要让 y_offset 漂移；
2. **呼吸幅度收敛到 0~1px**：当前是 1px，单帧内已经到视觉临界；如果美术管线允许，把 idle_1 的躯干带下移量改 0，呼吸完全交给整体微缩放（98.5% → 100%）；
3. **上半脸绝对静止**：眼睛/嘴的位移必须只发生在 blink/happy 帧，不能在 idle 里；
4. **frame interval 调整**：8fps (125ms) 在 1px 呼吸下偏快，可考虑 idle 用 4fps（250ms）让用户更易读出"呼吸"而非"抖动"。

> 本工单**未实际重新生成 sprite**——会破坏现有视觉资产，留待 M5 工单处理；本工单只产出脚本与数据。
