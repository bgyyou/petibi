# 桌宠交互动画设计（owner 2026-08-14 口述，主 agent 整理）

> 状态：设计定稿，待施工（blink/拖拽奔跑排近期，喂食排 V2 养成线）
> 原则：帧图一致性靠工程手段保证（镜像复用/程序合成/单图多帧），不赌生图模型的多视角一致性

## A. 眨眼 wink（V1 立即可做）

- 帧：idle 原图 → 闭眼帧 → idle 原图（已有 blink_0/blink_1）
- 节奏：随机间隔 3–6 秒触发一次，闭眼停留 ~150ms
- 实现：定时器随机调度，不打断其他状态

## B. 拖拽奔跑（V1）

- 触发：水平拖拽桌宠时进入跑步状态；松手回正面 idle
- 帧（每方向 2 帧循环，4–6fps）：
  - 帧 1：左手+右脚前（侧面视角）
  - 帧 2：右手+左脚前
- **向右跑 = 向左跑的水平镜像**（程序翻转，零一致性成本）
- 需生成：左侧视角跑步 2 帧（用"单图多帧法"：一次生成含两帧的图再切片）
- 拖拽垂直分量忽略（上下拖保持 idle）

## C. 喂食（V2，配合签到/分享养成线）

分镜（owner 原案 14 节拍）：
拿起食物张嘴 → 吃一口 → 食物剩一半 → 咀嚼×2 → 吃一口 → 食物剩一点 → 咀嚼×2 → 吃一口 → 食物没了 → 咀嚼×2 → 满足表情（持续 2-3 秒）→ 回 idle

工程拆解：
- **食物是独立图层**：3 张食物图（完整/半块/小块），程序合成到嘴边位置，不画进角色帧
- **角色只需 4 帧**：idle 原图、张嘴、咀嚼（闭眼鼓腮）、满足（笑眯眯）
- 节拍控制：每拍 300–400ms，满足表情 2-3 秒
- 不同食物 = 换食物图层（饼干/橘子/小鱼干），角色帧不变

## D. 一致性保障三板斧

1. **镜像复用**：左右对称动作只画一边
2. **程序合成**：道具/食物不进角色帧
3. **单图多帧**：必须新生成的多帧放同一张图里生成再切片

## E. 帧规范（沿用 style guide）

- 64×64 画布、1-bit alpha、色板内颜色、描边 #2B2320
- 校验：check_alpha + check_palette + 帧间对齐检查（check_idle_diff）
