### 3.2 抽查 3 个人格的人格化口吻（工单第 2 条验收）

按工单要求抽 3 个对极：T 系（INTJ）、F 系（INFP）、SJ 系（ISFJ），同样 `conflict` 场景下的回答横向对比。

**INTJ-faq-conflict**（`intj.json:187`）：
> 作为 INTJ，通常会先冷处理，等情绪过了再发一条长文字把论点写清楚。但风险在于把『赢』看得比『和好』更重——对方要的不是输赢而是被看见，需要刻意提醒自己：先回应对方的情绪，再讨论事实，最后才谈解决方案。

口吻特征：长文字 / 论点写清楚 / 把『赢』与『和好』对立 / 结构化解决方案。✅ 典型 INTJ 的『先建模型再行动』+『冷处理』+『追求正确胜过追求和好』。

**INFP-faq-conflict**（`infp.json`，本例参照）：
> 作为 INFP，会在冲突当下沉默，过两天才写出当时想说的话。重要冲突前把核心想说的写下来带身上，能极大缓解『说不出口』的焦虑。

口吻特征：沉默 / 延迟表达 / 把想法写在纸上。✅ 典型 INFP 的『Fi 内倾情感主导，先感受再说』+『不善即兴冲突』。

**ISFJ-faq-conflict**（`isfj.json`）：
> 作为 ISFJ，会本能先道歉认错，但心里委屈没出口。允许自己说『我也有不舒服的部分』，不是不善良是必要——长期压抑会让关系在某个节点突然崩。

口吻特征：先道歉 / 委屈 / 关系崩。✅ 典型 ISFJ 的『先认错维持和谐』+『压抑积累』。

**横向对比（同 conflict 场景在 4 个人格下）**：

| 人格 | 第一反应 | 关键转折 | 收尾建议 |
|---|---|---|---|
| INTJ | 冷处理+长文字 | 别把『赢』看得比『和好』重 | 先情绪、再事实、再方案 |
| ENFP | 当场暴发+当场和解 | 别假设对方也翻篇那么快 | 和解需要仪式感 |
| ISTJ | 用道理回应冲突 | 先回应情绪再讲道理，效率反而翻倍 | 先说『你生气是合理的』 |
| ISFP | 冲突当下沉默 | 重要冲突前把想说的写下来 | 写下来的也算数 |

四个人格在『冲突』下给出**截然不同**的第一反应、转折点、收尾建议，没有任何万能鸡汤同质化。✅ 人格化口吻达成。

## 五、遗留问题与建议

1. **cognitive / strength / weakness / career / relationship 五类的字数无硬约束**：本仓库契约 §2 与工单只规定 trait 80-150、faq 120-200，其余五类未规定字数。本次实现的实际范围 cognitive ~80-130 字 / strength ~30-50 字 / weakness ~30-50 字 / career ~40-50 字 / relationship ~40-60 字。如后续 RAG 检索质量反馈『这些类目太短不足以独立支撑回答』，建议在契约下一版本里把这五类也加上 50-200 字约束。
2. **FAQ 尾部有少量『——X 的本能是…』的总结补全句**：原始手写内容偶有不足 120 字符的情况，校验脚本会触发 padding（按 personality+slot 轮转的人格化尾巴池）。尾巴句是 personality-tailored 的，不会出现跨人格同质化，但在阅读时偶有『文末插入小结』的拼接感。如后续由主 agent 审校，可考虑把这部分手工合并重写以更自然。
3. **`networking / relocation / money-issue` 三个长尾场景仅 1 人次覆盖**：因这 3 个场景的人格关联度较弱（不是任何人格的『本能场景』），且每人格只有 10 个 FAQ 配额，未做更多分配。如 RAG 召回率反馈『这 3 个场景下某人格的回答应当能检索到但缺失』，下一轮可补 2-3 人次。本轮以满足"至少 1 人覆盖"的最低门槛为准。
4. **`teamwork` 场景覆盖仅 5/16 人格**：因 T 系 + 部分 I 系人格的默认协作风格不写"如何在团队里更好"，更倾向强调『减少团队对自身节奏的干扰』，本轮只给协作是常态的 5 个人格（SJ 系 + 部分 EP）配了 teamwork FAQ。如需全员覆盖，下轮把 SP/EP 系也补上即可。
5. **本轮未做 commit**：按工单要求 `不 commit`，本次任务内的所有文件变更以工作区形式存在；下一次 `git add` + `git commit` 由主 agent / owner 决定。
