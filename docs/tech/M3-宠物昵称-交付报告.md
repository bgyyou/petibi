# M3 宠物昵称工单交付报告

## 任务概述

工单要求：

1. `users` 表加字段：`pet_nickname`（TEXT，空 = 用动物本名）、`pet_nickname_changed_at`（INTEGER 时间戳）；
2. 新接口 `POST /api/me/pet-nickname`：首次设置不限；再次修改需距上次 ≥72 小时；昵称 1-8 字、去空格；
3. `GET /api/me` 响应带上宠物昵称 + 下次可改时间；
4. 主面板"我的"Tab 升级为真正的设置页（含修改入口 + 冷却倒计时）。

## 实现摘要

### 1. 数据库 schema 迁移

- 选 **ALTER TABLE 兼容旧库** 路径，不用删库重建（保留 M2 阶段已有的用户档案）。
- `server/src/db.ts` 新增 `ensureColumn()` 工具 + `PET_NICKNAME_COOLDOWN_SEC = 72*60*60` 常量；
- 在 `ensureSchema()` 末尾对 `users` 表加列：
  - `pet_nickname TEXT`（缺省 NULL = 未设置 = 用动物本名）
  - `pet_nickname_changed_at INTEGER NOT NULL DEFAULT 0`（0 = 从未改过，首次不受冷却）
- 用 `try/catch + /duplicate column name/i` 吞掉重复加列错误，保证 `ensureSchema` 多次启动幂等。
- `UserRow` 类型同步加上两个字段；`server/src/auth.ts` 中 `findUserById/findUserByEmail` 的 SELECT 都带上新列，并对老库数据 `pet_nickname ??= null / pet_nickname_changed_at ??= 0` 兜底。

### 2. 错误码 + 类型

- `server/src/errors.ts` 新增 `ErrorCodes.InvalidPetNickname` / `ErrorCodes.PetNicknameCooldown`。
- `AppError` 新增 `extra` 字段 + 工厂 `AppError.cooldown(code, msg, extra)`（HTTP 429）；
- `ApiErr` 增加 `extra?: Record<string, unknown>`；统一错误处理中间件 `app.ts` 把 `err.extra` 透传到响应体（前端 `parseJson` 反序列化时也对应带出来）。

### 3. 新接口 `POST /api/me/pet-nickname`

- 路由：`server/src/routes/me.ts` `POST /pet-nickname`；
- 校验：去全部 Unicode 空白后 1-8 字，否则 `400 INVALID_PET_NICKNAME`；
- 冷却判定：
  - `pet_nickname_changed_at <= 0`：首次写入，`changed_at = now`；
  - 否则 `next_change_at = changed_at + 72h`；若 `now < next_change_at` → `429 PET_NICKNAME_COOLDOWN`，`error.extra = { remainSec, nextChangeAt }`；
- 写入后再次 `SELECT` 回传 `{ pet_nickname, pet_nickname_changed_at, next_change_at }` 完整响应。

### 4. `GET /api/me` 响应扩展

- `MeResponse` 新增 `pet_nickname / pet_nickname_changed_at / next_change_at / pet_name / animal`；
- `pet_name` 与 `animal` 通过 `loadPersonaCard(mbti)` 从 `data/personas/<mbti>.json` 读取（未设 mbti 时为 `null`，人格资产缺失时兜底为 "伙伴"/"未知"，避免 5xx）；
- `EmailVerifyResponse.user` 同步带上 5 个新字段。

### 5. 前端 API client + types

- `src/api/types.ts`：`User` 加 5 个字段；新增 `SetPetNicknameRequest/Response`；`ApiError` 加 `extra?`；
- `src/api/client.ts`：
  - `mockSetPetNickname` 与 server 行为对齐（72h 冷却、1-8 字校验），写本地 `mockUser` 内存态；
  - `realSetPetNickname` 走 `fetch` 真接口；
  - 公共 `setPetNickname(token, req)` 同时支持 mock / 真接口；
  - `parseJson` 错误体透传 `extra`，`ApiCallError` 新增 `extra` 字段供 UI 用。

### 6. 主面板"我的" Tab 升级

- 新组件 `src/panel/tabs/ProfileTab.tsx`：
  - 三段卡片：用户档案（昵称/邮箱/MBTI/细分/动物）、宠物昵称（值 + 修改入口 + 冷却倒计时）、未来功能占位；
  - 编辑器四态状态机：`idle / editing / saving(draft) / cooldown(remainSec, nextChangeAt)`；
  - 冷却中：按钮置灰 + 文本"X 小时 Y 分后可改"；提交被拒后再次展示剩余时间；
  - 1 Hz `setInterval` 推动倒计时秒级刷新；
  - `Enter` 提交、`Escape` 取消；
- `src/panel/App.tsx`：用 `ProfileTab` 替换原 `PlaceholderTab`；`getInit()` 取 token → `getMe()` 拉 server user → 通过 `user/token/onUserChange` 三 prop 注入 ProfileTab；
- `src/panel/styles.css` 新增 `.profile-shell` / `.profile-card` / `.profile-nickname-row` / `.profile-btn-*` 等样式，复用既有纸感底色板（暖色 `#8a6a1e` 高亮 + 圆角卡片）。

## 注意事项 / 后续工作

- `findUserByEmail` / `findUserById` 在老库上若 `pet_nickname` / `pet_nickname_changed_at` 为 `undefined`（缺列而非 NULL），已统一兜底为 `null / 0`；下次 `ensureSchema` 跑过一次 ALTER TABLE 后会自动收敛，不再走兜底分支。
- `EmailVerifyResponse.user` 新增 5 个字段；旧客户端若用 `as User` 强转，TypeScript 会因字段缺失报错（前端 `VerifyCodeResponse.user: User` 已同步更新，无破坏）。
- ProfileTab 的 1Hz `setInterval` 仅在组件挂载期间运行；切到其他 Tab 时组件仍挂载（Panel 不卸载子组件），所以切回来倒计时不会断。
- 未做的工作（不在本工单范围）：文案本地化、键盘无障碍属性（仅基础 aria-label）、面板内"未来功能"链接占位。
