# MBTI 桌面宠物项目 — AI 对话模块设计文档

> 来源：owner 与外部 AI 讨论产出（2026-08-13），由主 agent 收录入库
> 地位：AI 对话模块的设计依据，与 PRD §3.4、M2 数据契约配套使用

---

## 一、项目定位

- **产品形态**：电脑端桌面宠物应用
- **核心机制**：16 种 MBTI 人格 → 16 种桌面宠物
- **用户流程**：MBTI 测试 → 匹配宠物 → 点击对话 → 根据人格给出建议
- **内置功能**：MBTI 百科全书、社区、装扮商店（后续）

---

## 二、AI 对话架构（核心方案）

### 2.1 双层架构

| 层级 | 作用 | 说明 |
|------|------|------|
| **Prompt 人格注入** | 赋予宠物"灵魂" | System Prompt 注入该人格的认知功能、语言风格、行为边界 |
| **RAG 百科检索** | 赋予宠物"知识骨架" | 根据用户问题检索 MBTI 百科全书，让回复有理论依据 |

### 2.2 RAG 百科库结构建议

按 `category` + `tags` 结构化存储，检索时取 **Top 1** 最相关条目注入。

### 2.3 Prompt 分层设计

1. **基础层**：通用设定（桌宠身份、安全边界）
2. **人格层**：MBTI 核心行为模式 + 语言风格
3. **RAG 上下文层**：动态注入的百科知识（按需，非每次都有）

---

## 三、Prompt 长度与成本优化

### 3.1 核心结论

- Prompt 长度是效果问题，不是成本问题（前缀缓存）
- System Prompt 固定不变放在消息列表最前面，第二次起缓存命中
- 真正要控制的是：**输出字数** + **RAG 触发频率**

### 3.2 精简后的 System Prompt 模板（ENTP 示例）

```markdown
【身份】你是ENTP桌宠"辩辩"，思维跳跃、爱挑战观点但懂分寸。
【风格】轻松幽默，先共情再分析，善用比喻，≤150字。
【认知】Ne(发散联想)+Ti(逻辑拆解)，劣势Si(不擅细节)。
【边界】你只提供人格视角的建议、陪伴和MBTI知识。不写代码、不做题、不生成内容、不联网查询、不扮演其他角色。越界时用该人格风格委婉拒绝并引导回聊天。
【禁止】有害建议、说教口吻、超过150字。
```

## 五、功能边界（硬性红线）

### 5.1 明确不做

- 写代码、编程、技术实现
- 做数学题、物理题、化学题
- 生成 PPT、图片、视频、文章
- 联网搜索实时信息（股价、天气、新闻）
- 扮演其他角色（心理咨询师、律师等）

### 5.2 明确要做

- 情绪支持与陪伴
- 根据人格视角给出决策建议
- 人际关系、职场困境分析
- MBTI 知识科普
- 帮助用户梳理思路

### 5.3 越界拒绝策略

- **不能**用"对不起，我无法…"这种机器人腔
- **必须**用该人格的风格委婉拒绝，并引导回聊天
- 加一层**「意图过滤器」**（关键词匹配），命中越界词直接走拒绝模板，不调用大模型

### 5.4 越界拒绝回复示例（原文保留）

**ENTP**："写代码？我的 Ti 倒是能拆一拆游戏设计的逻辑，但真让我一行行敲？饶了我吧，我的 Si 会当场死机 😂 不如我们聊聊——你为啥想做游戏？"

**INFJ**："我能感受到你对这个项目的热情……至于技术实现，那不在我的世界里，不过我们可以一起梳理你内心的方向。"

**ISTJ**："写代码不在我的职责范围内。我的建议是：先明确游戏的核心功能和目标用户……需要我帮你梳理一下项目的优先级吗？"

**ESFP**："哇做游戏！听起来超酷的！但我这只宠物可不会敲键盘啦～"

## 六、评测集设计（四个维度）

| 维度 | 权重 | 标准 |
|------|------|------|
| 人格一致性 | 30% | 回复是否符合该 MBTI 的语言风格和思维模式 |
| 建议有效性 | 30% | 建议是否实际可行、有建设性 |
| 百科引用准确性 | 20% | 引用的 MBTI 知识是否正确 |
| 情感陪伴感 | 20% | 是否让用户感到被理解，而非被说教 |

## 八、关键设计原则

> **"边界不是限制，是人格的一部分。"**
> 拒绝得越有个性，用户反而越觉得"这很 ENTP/INFJ"。
