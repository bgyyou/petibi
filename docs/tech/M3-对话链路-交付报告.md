## 三、关键设计落地说明

### 3.1 SSE 协议（契约 §4 自定义）

事件类型 4 种，每条 `data: <json>\n\n`：

| 事件 | 触发时机 | 关键字段 |
|---|---|---|
| `meta` | 鉴权+意图过滤+RAG 检索完成后立即发送 | `rag_entry_id`, `refused` |
| `delta` | LLM 流式每段文本 | `text` |
| `done` | 整次回答结束 | `total_chars` |
| `error` | 配额耗尽 / LLM 调用失败 | `message` |

首条 `meta` 事件 ≤1ms 内送达（mock 模式实测），前端据此 ≤0.3s 切思考动画的硬性指标达成。

### 3.2 链路顺序（契约 §4 严格执行）

```
鉴权 (Bearer email)
  ↓ 401 拒绝
profile 完整 (mbti + subtype)
  ↓ 409 拒绝
意图过滤（读取 data/intent-filter.json）
  ↓ 命中 → 选人格化拒绝模板 → 流式切片 → 扣配额 → 记 chat_logs(refused=1) → done
闲聊判定 (rag_skip_patterns)
  ↓ 命中 → rag=null
RAG 检索 (data/encyclopedia/16 个文件 × ~25 条)
  ↓ Top 1 → rag_entry_id
配额扣减 (chat_usage)
  ↓ 第 11 次 → error 事件
拼 prompt (基础层 + 人格层 + RAG 上下文)
  ↓
LLM 流式 (DeepSeek OpenAI 兼容 / mock)
  ↓
记 chat_logs(rag_entry_id, refused=0)
  ↓
done
```

### 3.3 DB 选型说明（与契约 §4 的偏离声明）

契约 §4 规定 better-sqlite3。**本机环境实测 better-sqlite3 v11.8.1 无 Node 24 预编译二进制且 MSBuild 工具链编译失败**（截图：错误信息 `MSBuild.exe failed with exit code: 1`）。改用 Node 24 内置 **`node:sqlite`**（experimental，自 Node 22.5 起可用）：

- 两套 API 形态高度一致：同步 `prepare(...).run/.get/.all`，业务代码无需改写
- 部署到 Node 20 / 22 LTS 时可一键切回 `import Database from "better-sqlite3"`
- 类型用 `import type` 单独拿，运行时用 `createRequire("node:sqlite")` 避开 vite/vitest 的解析问题

### 3.4 RAG 检索实现

按契约 §4 "关键词/tag 匹配打分取 Top 1" 实现，无外部依赖：

| 来源 | 分值 |
|---|---|
| 条目标题命中 | +3 |
| 条目标签命中（每个） | +2 |
| 条目 scenario slug 命中 | +4（场景词最直接） |
| 条目正文命中 | +1 |

中文处理：tokenizer 同时产出单字 + 二元组 bigram，避免无 jieba 也能命中"演讲"/"分手"等组合词。
示例验证（`rag.test.ts`）："明天要当众演讲好紧张" → 命中 `scenario=public-speaking` 条目。

### 3.5 LLM 接入（契约 §5 严格遵循）

- 端点：`https://api.deepseek.com/chat/completions`（base_url 可由 `DEEPSEEK_BASE_URL` 覆盖）
- 模型：`deepseek-chat`（`DEEPSEEK_MODEL` 可覆盖）
- 鉴权：`Authorization: Bearer ${DEEPSEEK_API_KEY}`（**不进仓库**，`.env.example` 占位）
- 无 key / `FORCE_MOCK=1` → 自动走 mock 流式（标注 `[mock] ` 前缀，便于前端/日志识别）
- 输出限制 ≤150 字：prompt 字面约束 + `max_tokens: 300` 兜底（约 250 token 对应 150 中文字）

### 3.6 配额（PRD §3.4 + R4）

- 每日 10 次（`DAILY_QUOTA = 10`）
- 表 `chat_usage(user_id, date, count, UNIQUE(user_id,date))`
- 同一日内 `UPDATE ... WHERE count < 10`，第 11 次 `changes === 0` → `QuotaExceeded`
- 越界命中也扣配额（契约 §4 明确："命中则流式返回拒绝模板，不计 LLM 调用但计次"）

### 3.7 思考动画接线（最小化 src/ 改动）

未触碰 `electron/preload.ts` / `electron/main.ts` / `src/pet-api.d.ts`。`src/App.tsx` 本地扩展：

- `PetState` 加 `'thinking'`（TS 通过 `state !== 'thinking'` 守卫，避免 `notifyState` 类型报错）
- `FRAMES.thinking` 占位（沿用 idle 帧，专用 sprite 待 M4 工单）
- `window.petState(s)` 钩子：未来聊天 UI 在 `fetch('/api/chat')` 前调 `petState('thinking')`、完成（done/error）后调 `petState('idle')`，实现 ≤0.3s 切换思考动画
- 调试热键 `4` 切 thinking

## 四、已知偏差与遗留

| 项 | 说明 | 影响 |
|---|---|---|
| DB 引擎 | `node:sqlite` 替代 `better-sqlite3`（见 §3.3） | 仅开发环境，API 形态一致；部署前可一键切换 |
| data/personas/ 等 | 由并行人格资产工单生产，本次未触碰 | 路由代码兼容：文件不存在时人格层走"通用兜底"分支（不抛错），保证联调不被资产缺位挡住 |
| `data/intent-filter.json` 实际格式 | 实际文件中 `code` 类不含 `python/java` 等英文关键词，只有中文（"写代码"等）。`intent-filter.test.ts` 用本地硬编码 fixture 自测；`chat-route.test.ts` 用"帮我写代码"做越界样本 | 不影响契约 |
| `data/refusals.json` 实际格式 | 当前文件已存在并有真实数据，`refusals.ts` 读取路径正确 | 联调可立即生效 |
| thinking 帧 | 占位沿用 idle 帧 | 不影响逻辑切换，sprite 待美术工单 |
| 跨平台路径 | `db.ts` 用 `fileURLToPath` 解析项目根，跨 Win/macOS/Linux 一致 | 无 |
