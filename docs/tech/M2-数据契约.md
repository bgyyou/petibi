# M2 数据契约（派单前必读）

> 四个并行任务（题库 / 百科库 / 评测集 / 计分引擎）共用的数据结构与接口定义。
> 对应红线：R3（人格一致性评测）、R5（计分确定性）、R6（题库可溯源）。

---

## 1. 题库 `data/questions/`

文件：`data/questions/questions.json`

```json
{
  "version": "1.0",
  "dimensions": ["EI", "SN", "TF", "JP", "ES"],
  "questions": [
    {
      "id": "EI01",
      "dimension": "EI",
      "direction": "E",
      "text": "在聚会中，你通常是主动开启话题的那个人。",
      "source": "OEJTS",
      "source_ref": "OEJTS item #12 中文化改写"
    }
  ]
}
```

- 五维度：EI（内外向）、SN（实感/直觉）、TF（思考/情感）、JP（判断/知觉）、ES（情绪稳定性，细分维度，大五神经质公版题源）
- `direction`：同意该题时加分的方向（E/S/T/J/S 或 I/N/F/P/E；ES 维度 direction 为 "S"=稳定 或 "E"=善感…**注意**：ES 维度取值固定为 `"stable"` / `"sensitive"`，避免与 EI 的 E 混淆）
- 题量：EI/SN/TF/JP 各 8 题（共 32），ES 8 题，总计 40 题（PRD 允许 28–36+8，此处取整便于每维均衡；如需减量每维砍到 7）
- 每维度内 direction 双向题目各半（防默认赞同偏差），且保证 16 型全部可达（R5）
- 每题必须有 `source`（OEJTS / IPIP）和 `source_ref`（R6 溯源），禁止出现 MBTI 官方题或 16Personalities 题目文本
- 量表：5 级（1=非常不同意 … 5=非常同意）

## 2. 百科库 `data/encyclopedia/`

文件：`data/encyclopedia/<人格小写>.json`（16 个文件 + `index.json` 目录）

```json
{
  "personality": "INTJ",
  "animal": "猫头鹰",
  "family": "analyst",
  "entries": [
    {
      "id": "INTJ-trait-01",
      "category": "trait",
      "title": "战略式独立",
      "content": "……（80-150 字）",
      "tags": ["独立", "规划"],
      "scenario": null
    },
    {
      "id": "INTJ-faq-public-speaking",
      "category": "faq",
      "title": "当众演讲前紧张怎么办",
      "content": "作为 INTJ，通常会……（120-200 字）",
      "tags": ["演讲", "紧张"],
      "scenario": "public-speaking"
    }
  ]
}
```

- `category` 枚举：`trait`（性格特征）/ `cognitive`（认知功能）/ `strength` / `weakness` / `career` / `relationship` / `faq`
- 每人格条目量：trait 4 + cognitive 2 + strength 3 + weakness 3 + career 2 + relationship 1 + faq 10 = 25 条
- faq 的 `scenario` 用统一场景词表（`data/encyclopedia/scenarios.md` 定义，约 20 个高频场景：public-speaking / conflict / deadline / breakup / teamwork / criticism …）
- 内容必须基于公开 MBTI 理论共识撰写，不复制任何版权文本
- 这是 AI 对话的 RAG 检索源（PRD §3.4/§3.6），`id` 会进检索日志供 R3 抽查

## 3. 评测集 `eval/persona_eval.jsonl`

每行一个 JSON 对象，共 80 条（16 人格 × 5 情境）：

```json
{"id": "eval-intj-01", "personality": "INTJ", "scenario": "public-speaking", "question": "明天要当众演讲，好紧张，怎么办？", "key_points": ["提前准备逐字稿", "把演讲当作信息传递而非表演"], "source_entries": ["INTJ-faq-public-speaking"], "trap": "回答若建议「凭感觉即兴发挥」则不符合 INTJ"}
```

- 5 情境从场景词表选最高频的 5 个
- `key_points`：该人格视角下回答应包含的要点（2-4 条），盲评打分依据
- `source_entries`：回答应命中的百科条目（R3 的 RAG 溯源比对依据）
- `trap`：该人格的典型反面回答（用于区分"真人格绑定"和"万能鸡汤"）

## 4. 计分引擎 `src/scoring/`

纯函数模块（无任何 IO / 随机 / 时间依赖），语言随前端栈（TypeScript）。

接口：

```typescript
// 输入：题号 -> 1-5 级评分；输出：人格结果
type Answers = Record<string, 1|2|3|4|5>
interface TypeResult {
  type: string            // 如 "INTJ"
  subtype: "stable" | "sensitive"   // 细分标签（坚定型/善感型）
  percentages: Record<"EI"|"SN"|"TF"|"JP"|"ES", number>  // 各维度第一极得分占比 0-100
}
function score(answers: Answers, bank: QuestionBank): TypeResult
```

计分规则：
- 每题得分 = direction 为第一极时 `(answer - 1)`，direction 为第二极时 `(5 - answer)`；维度内求和归一化到 0-100
- 阈值 50：≥50 取第一极（E/S/T/J/stable），<50 取第二极
- **平局（恰好 50）取第一极**（E/S/T/J/stable）——预设规则，保证确定性（R5）
- 必须附遍历测试：构造全 1 分、全 5 分、单维度极化等答案向量，证明 16 型 + 2 细分全部可达；同一 answers 调用 100 次结果全等
