## 3. 步骤 2：v5 严格校验脚本

### 3.1 设计

新增 `scripts/check_portraits_v5.py`，比 v4 检查更严格：

| 维度 | v4 check_portraits_v4.py | v5 check_portraits_v5.py |
| --- | --- | --- |
| 1. 尺寸 | ✅ | ✅ |
| 2. 色板合规（不含白底） | ✅ | ✅ |
| 3. 头部区毛色规避四族色 | ✅ | — |
| 4. 全图无其他族色 | — | ✅ |
| 5. **服装区主色 = 本族 main** | （整图） | （严格彩色像素分布） |
| 6. 同族 main 像素级一致 | ✅（打印） | ✅（打印 + 统计服装区 main 像素数） |

**服装区定义（v5 严格口径）**：全图范围内，排除白底 / 中性色 / 描边后，剩下饱和度（max-min）≥ 35 的彩色像素。等价于"角色本体（非头非背景）的彩色设计像素"。

> 设计过程踩坑：第一版用 y∈[0.40, 0.95) 的"服装区"切片，导致 INFP 在 y=0.4-0.6 段（蝴蝶翅膀覆盖躯干区）shadow ×2988 vs main ×420 → 误报失败。改用全图"非中性色/非描边/非白底"语义后 INFP 通过（全局 main×15192 vs shadow×8900，main 严格主导），与 v4 检查 4 一致。

## 7. 没把握的部分（诚实）

- **ENTJ**：v4 定稿后 ENTJ 的 main ×8052 是全表最低之一，shadow/light/highlight 都为 0，ENTJ 服装可能面积偏小（紫色正装外套袖子+领带占主体）。数值上 main 主导没问题，但视觉上 ENTJ 是服装覆盖最少的，下一步如果 owner 觉得 ENTJ 紫色不够明显，可能需要重生成。
- **ESTP**：服装 main ×6724（explorer 族最低），highlight ×5188 第二多 → 黄色服装上 highlight（浅黄高光）占了一定面积。数值上 main 仍是第一多，符合工单，但黄色 + 高亮容易在 32×32 sprite 量化后被并入同类。
- **INFP**：全局 main 主导，但 y∈[0.4, 0.6) 段（蝴蝶翅膀覆盖躯干）shadow ×2988 vs main ×420。本 v5 检查因定义改为全图语义而通过，但若后续 sprite 化时翅膀阴影和躯干阴影被合并为同色块，可能在 32×32 sprite 上呈现"整体偏暗绿"印象。
- **ESFJ**：main ×9336（sentinel 族最低），shadow ×5892 第二多 → 服装面积相对小（粉/棕大象 + 背心款），但仍 main 主导。无明显问题，仅作备注。
- **同族 main 像素级一致**指 main RGB 值相同（取自同一色板字段），不是服装形状相同 —— 各人格服装款式仍保留差异化设计。
