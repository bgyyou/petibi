## 1. 实现要点

### 1.1 双窗口设计

按关键决策「流程页开新正常窗口，桌宠悬浮窗保留 128×128」，主进程拆成两个 BrowserWindow：

| 窗口 | 尺寸 | 属性 | 加载入口 |
|---|---|---|---|
| setup（初始化）| 800×640 | 正常应用窗口：有框 / 不透明 / 进任务栏 / 居中 | `setup/index.html`（dev 下 `${devUrl}setup/index.html`） |
| pet（桌宠）| 128×128 | 沿用 M1：透明 / 无边框 / alwaysOnTop / 128×128 | `index.html`（dev 下 `${devUrl}`） |

启动时分流：主进程读 `userData/profile.json`，若 `profile.mbti` 已存在 → 直接开 pet；否则开 setup。

### 1.2 主进程 / preload 桥接

- `electron/storage.ts`：原子写入（`.tmp` → `rename`）的 `profile.json` 读写器
- `electron/main.ts`：新增 IPC handler `profile:get` / `profile:set`，event `setup:complete` / `setup:cancel`
- `electron/preload.ts`：contextBridge 暴露 `getProfile` / `setProfile` / `completeSetup` / `cancelSetup` / `spriteUrl`（相对 URL，不返回 file:// 硬编码，符合工单硬性要求）
- 渲染进程侧 `src/pet-api.d.ts` 同步扩展

### 1.3 API 客户端层（mock 优先）

`src/api/client.ts` + `src/api/types.ts`：

- 5 个端点：`sendEmailCode` / `verifyEmailCode` / `getMe` / `saveProfile` / `submitFeedback`，全部对齐 `docs/tech/M3-对话链路契约.md §4`

## 5. 已知遗留与建议

1. **`buildDependenciesFromSource` / `npmRebuild`**：本次新增了 `electron-builder.yml` 的 `npmRebuild: false` 来跳过 better-sqlite3 的 electron-rebuild。原因是并行工单把 server 依赖装到了根 node_modules。长期方案：server 拆到独立 package 目录（如 `server/package.json` 自带 node_modules），或用 workspace。本任务范围内不动 server，最小修复如上。
2. **`pickedType` 路径的 subtype 默认值**：用户在 PickTypePage 直接选用人格时，`pickedType` 没有 subtype 信息，ResultPage 默认按 `stable` 显示。后续若细分标签有强需求，可加「再测一下情绪稳定性」可选测试。
3. **本地存储位置**：`profile.json` 落在 Electron `userData` 目录（Windows 下通常 `%APPDATA%/Petibi/`）。如未来要做多用户切换，需要重构为主键分目录或多文件。
4. **未做：国际化**：所有 UI 文案为简体中文，按当前 MVP 范围足够。
